Choose the `cratis` template for a full-stack C# application with Cratis Arc handling commands and queries, Cratis Chronicle storing events, and a React frontend calling generated TypeScript proxies. You start the backend, frontend, and Compose infrastructure separately. If you want an app host to start the backend and containers together, choose the [Cratis Aspire template](/templates/cratis-aspire/) instead.

You need the .NET 10 SDK (`net10.0` is the only target framework), Docker with the Compose plugin, and Node.js `^20.19.0` or `>=22.12.0`. Have yarn available for the default frontend commands. [Install the templates](/templates/getting-started/#install-the-templates) before creating the project if the package is not installed.

```bash
dotnet new cratis -n MyStore
cd MyStore
```

The project and compose file are in MyStore; use that directory for the remaining commands. Check that the scaffold's frontend dependency installation completed, or follow the generated README's install step before starting Vite.

Use this development configuration only on a trusted machine. With default MongoDB, removing the Chronicle container deletes its events and read models. To start the application, follow [Getting started](/templates/getting-started/) from Start the infrastructure onward, without scaffolding a second project. Compose runs the containers; the backend and Vite use separate terminals. The sample below explains what happens when you register a name.

## Options

| Option | Values | Default |
| --- | --- | --- |
| `--Database` | `MongoDB`, `PostgreSQL`, `MsSql`, `SQLite` | `MongoDB` |
| `--packageManager` | `yarn`, `pnpm`, `npm`, `none` | `yarn` |
| `--Framework` | `net10.0` | `net10.0` |
| `--SkipAiUpdateInstructions` | `true`, `false` | `false` |

Keep MongoDB for the default walkthrough. Choose another database at creation time, in place of the first scaffold command; the alternative command below is not a next step to run inside MyStore.

With a database other than MongoDB, the project references `Cratis.Arc.EntityFrameworkCore` instead of `Cratis.Arc.MongoDB`, and `appsettings.json` sets `Cratis:Chronicle:DefaultSinkTypeId` to `SQL`. Chronicle then projects read models into a table (`Listings`) in a database named `chronicle+<your event store>`, and `ConnectionStrings:Cratis` points Entity Framework Core at that database. The Chronicle container in `docker-compose.yml` stores its data in a PostgreSQL or SQL Server container, or, for SQLite, in a `chronicle-data` folder in your project that the backend reads directly:

```bash
dotnet new cratis -n MyStore --Database PostgreSQL
```

## The sample slices teach the conventions

The `Registration` slice shows the command side: a model-bound command that returns the event source id it chose plus the event to append. There is no controller, handler class, or route registration. This excerpt from `SomeModule/SomeFeature/Registration/Registration.cs` omits the event and reactor declared in the same file:

```csharp
[Command]
public record Register(SomeName Name)
{
    public (SomeId, Registered) Handle()
    {
        var eventSourceId = SomeId.New();

        return (eventSourceId, new(Name));
    }
}
```

`SomeId` is a strongly-typed identity — a `Guid`-backed value deriving from `EventSourceId<Guid>` — rather than a raw `Guid`. Every feature gets its own identity type this way instead of passing bare `Guid`s around.

The `Listing` slice shows the read side: a read model projected from `Registered` events, with an observable query for all instances. `Name` maps from the event by convention, and `[SetFromContext]` copies the event source id from the event's context. This is the MongoDB variant from `Listing/Listing.cs`; the other databases query `CratisAppDbContext` instead:

```csharp
[ReadModel]
[FromEvent<Registered>]
public record Listing(
    Guid Id,
    SomeName Name,
    [SetFromContext<Registered>(nameof(EventContext.EventSourceId))] EventSourceId EventSourceId)
{
    public static ISubject<IEnumerable<Listing>> AllListings(IMongoCollection<Listing> collection) =>
        collection.Observe();
}
```

With Chronicle and the backend running, send the request below to register a name without opening the dialog. It calls the same Register command as the sample UI: the command chooses an identity and returns Registered, which the Arc integration appends to Chronicle. The reactor and projection consume that event separately; check the response, backend log, and list for their different parts of the result.

```bash
curl -X POST http://localhost:5000/api/some-module/some-feature/registration \
  -H "Content-Type: application/json" \
  -d '{ "name": "Cratis" }'
```

A successful response carries `"isSuccess":true` and the new identity in `response`. The backend reactor logs `Registered: Cratis`; that line is not a check of the projected read model. Open the frontend's **Demo** page and look for the name in its list. If the application cannot connect or start, use the [Getting started troubleshooting steps](/templates/getting-started/#troubleshooting) and inspect the Chronicle service's Compose logs.

When you finish, stop the backend and Vite in their terminals. With default MongoDB, removing the Chronicle container deletes the events and read models held inside it. Use `docker compose stop` to pause the containers and keep that data; use `docker compose down` only when you intend to remove the containers and their default MongoDB data.

The route comes from the namespace: `CratisApp.SomeModule.SomeFeature.Registration` with the root namespace's segments skipped (`Program.cs` post-configures `SegmentsToSkipForRoute` to the namespace segment count, paired with the MSBuild count of `RootNamespace` for `CratisProxiesSegmentsToSkip`) and the command name left out (`IncludeCommandNameInRoute: false`). These settings live in `appsettings.json` and have matching `CratisProxies*` properties in the `.csproj`; change them together, or the generated proxies call routes the backend does not map. See [Proxy generator configuration](/arc/backend/csharp/proxy-generation/configuration/).

## TypeScript proxies are generated at build time

The project configures `dotnet build` to write typed TypeScript proxies next to their C# sources: `Registration.cs` produces `Registration.ts`. The frontend imports that generated contract to call the backend. Rebuild after changing a command or query, then update frontend code where its use no longer matches the generated shape.

From a file in the `Registration` folder, you can execute the command directly:

```typescript
import { Register } from './Registration';

const command = new Register();
command.name = 'Cratis';
const result = await command.execute();
```

The sample UI does not call `execute()` itself. `RegisterDialog.tsx` passes the `Register` type to a Cratis Components `CommandDialog`, which binds the form fields and executes the command.

## Add your first feature

Start by changing the sample's registered name and following it from the command to the backend log and list. Then copy the `SomeFeature` folder shape for your own behavior: one folder per feature, one folder per slice, C# and TypeScript side by side. Keep the command, its read-side view, and the React components connected through their generated proxies; the route settings described above must stay paired when you rename the root namespace. Optional AI guidance follows this same slice structure.

## AI assistance

AI assistance is optional; you can run and change the sample without installing agent guidance. The scaffolded project's `.cratis/ai.json` selects `cratis/application/csharp` with C# and TypeScript for the full-stack application. If you want that guidance, install the [Cratis CLI](/cli/) and run this from the MyStore project root:

```bash
cratis ai update
```

That installs the AI rules, skills, and harness integration for the coding agents you selected (`AGENTS.md` plus `.claude/`, `.cursor/`, `.github/`, `.opencode/`, and `.pi/`) and records what it installed in `.cratis/ai.manifest.json`. `dotnet new` prints this reminder after scaffolding; `cratis new` runs the update for you. Running it again refreshes only Cratis-managed files. See the [CLI AI documentation](/cli/ai/) for the full command reference.
