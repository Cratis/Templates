Use the cards below to choose a host and language. Install the templates once per machine, then follow [Getting started](/templates/getting-started/) for the C# full-stack walkthrough. Kotlin and Java readers should use their own template guide rather than follow the C# run commands:

```bash
dotnet new install Cratis.Templates
```

`Cratis.Templates` contains every template, including the Kotlin and Java versions of the full-stack application: `dotnet new cratis --language Kotlin` or `--language Java` selects them. The JVM templates are also published on their own as `Cratis.Templates.Kotlin` and `Cratis.Templates.Java`, and the [Cratis CLI](/cli/new/) can scaffold every template with `cratis new`.

## What the application templates have in common

The full-stack templates (`cratis` in C#, Kotlin, or Java, and `cratis-aspire`) share application concepts, but use different hosts, builds and file layouts. Use the chosen template's guide for its actual setup:

- **Vertical slices.** Each behavior is one slice: the command or query, the events it produces, and the React component that calls it through a generated TypeScript proxy. In the C# templates all of it shares one folder. In Kotlin and Java the backend slice lives under `src/main/`, its React components under `SomeModule/`, and the proxies under `build/generated/arc-proxies/`.
- **Model-bound by default.** Start from the sample command and read-model declarations in the chosen template; its language guide explains how those declarations become routes.
- **Local infrastructure included.** `cratis` ships a `docker-compose.yml` that starts the Chronicle development image (MongoDB bundled) and an Aspire dashboard. `cratis-aspire` starts Chronicle from its Aspire app host instead.
- **AI-ready.** Every template, including the two Chronicle client templates, ships a `.cratis/ai.json` that selects its Cratis AI profiles, languages, and coding-agent harnesses. Installing that guidance is optional: run `cratis ai update` after `dotnet new` if you want it; `cratis new` does it for you. See [Cratis AI in the CLI](/cli/ai/).
- **Build before extending.** Build the generated application before editing the sample so you can distinguish toolchain and package diagnostics from changes you make to the domain.

## Package versions

- **.NET templates.** The template source references Cratis packages with a floating `Version="*"`. Post-creation actions request package additions without an explicit version and can continue after an error. Inspect the generated `.csproj` and the post-action output before treating the resolved package versions as your starting point.
- **Kotlin and Java templates.** `build.gradle.kts` requests the Arc Gradle plugin (`io.cratis.arc`) and the `io.cratis:cratis` dependency as `latest.release`. Treat `io.cratis:cratis` as a dependency declaration to resolve, and use the JVM guide for backend setup instead of copying the C# walkthrough. Gradle caches a dynamic version for up to 24 hours by default; `./gradlew build --refresh-dependencies` picks up a release published since. For reproducible builds, replace `latest.release` with an exact version, or use Gradle dependency locking.
- **Frontend.** `package.json` uses caret ranges. Commit the lockfile your package manager writes to record exactly what you installed.

## Project names with dots

You can scaffold with `-n Contoso.Shop` in `dotnet new` or `cratis new` without changing your namespace: it keeps the dotted name. Your event store and database names drop dots and other characters MongoDB forbids, giving you `ContosoShop`; class names use underscores, such as `Contoso_ShopDbContext` and `Projects.Contoso_Shop`. In the C# application templates, proxy and route segment skipping follows your project name without a fixed segment limit: MSBuild counts `RootNamespace` for the proxies, while `Program.cs` post-configures Arc's route count from the same namespace. If you rename that namespace later, update both settings together.

Keep your event store names short: Chronicle appends suffixes such as `+es+Default`, and MongoDB limits database names to 63 bytes.

## Reproducible builds

Capture what scaffolding and the first build actually resolve before you extend the sample. Floating declarations and installed package versions are different things; keep the resolved versions and container identities if you need to reproduce that starting point:

- **.NET:** After successful package post-actions, inspect the resolved versions; to lock transitive packages too, set `<RestorePackagesWithLockFile>true</RestorePackagesWithLockFile>`, commit `packages.lock.json`, and restore with `--locked-mode` in CI.
- **JVM:** Enable Gradle dependency locking and run `./gradlew dependencies --write-locks`; commit the lockfiles.
- **Frontend:** Commit your package manager's lockfile.
- **Containers:** Run `docker compose config --resolve-image-digests` to print your compose file with each image resolved to `name@sha256:…`; commit that output or copy the digests into your compose file. Use `docker compose images` or `docker image inspect --format '{{index .RepoDigests 0}}' cratis/chronicle:latest-development` to see what you run.
- **Aspire:** Set `.WithImageSHA256("…")` on your Chronicle resource to use the digest you captured.
