---
title: The Chronicle Console template
description: The shortest path to a running Chronicle application — a console app that appends an event and observes it through a projection and a reactor.
---

Use the `cratis-chronicle-console` template to try an event flow without an HTTP layer or frontend. The console app connects to Chronicle, appends a sample event, and leaves the terminal open so you can see its reactor handle that event.

You need the .NET 11 SDK and Docker with the Compose plugin. If the template package is not installed, [Install the templates](/templates/getting-started/#install-the-templates) before creating the project.

```bash
dotnet new cratis-chronicle-console -n MyConsole
cd MyConsole
```

The example creates a MyConsole directory. Keep subsequent commands in that directory, where the generated project and compose file live.

## Options

| Option | Values | Default |
| --- | --- | --- |
| `--Database` | `MongoDB`, `PostgreSQL`, `MsSql`, `SQLite` | `MongoDB` |
| `--Framework` | `net11.0` | `net11.0` |
| `--SkipAiUpdateInstructions` | `true`, `false` | `false` |

The template scaffolds a Chronicle **client**. `--Database` changes only where the Chronicle kernel in `docker-compose.yml` stores its data; the console code is the same for every choice.

## What you get

Start with `Program.cs`: the append creates TestEvent, TestProjection describes the read model built from it, and TestReactor prints the event's message. The console does not query the projection, so the terminal output below demonstrates the reactor, not the read model's contents. The file contains:

- A `ChronicleClient` created without arguments, which connects to the local development kernel (`chronicle://localhost:35000` with the development client credentials), and an event store named after your project.
- A `[EventType]` record, `TestEvent`: the fact your application produces.
- A model-bound `[FromEvent<TestEvent>]` read model, `TestProjection`, kept in sync by Chronicle.
- An `IReactor`, `TestReactor`, that prints each `TestEvent` it observes.

## Run it

The generated configuration uses development client credentials; run it only on a trusted development machine. From the MyConsole directory, start the infrastructure, then run the app from an interactive terminal. Compose starts the containers in the background; the console app runs in this terminal. If the client cannot connect, inspect the Chronicle service's logs in Docker Compose before starting another app instance:

```bash
docker compose up -d
dotnet run
```

The app appends one `TestEvent`. Its reactor is the part that writes this terminal line:

```text
Received event with message: Hello world!
```

The main program waits for a key press. Leave the interactive terminal open until you see the reactor line above, then press any key to exit. Redirected input does not provide that key-press interaction. Each run appends another event to the same event source, `some-event-source`.

With the default MongoDB setup, events are stored inside the Chronicle container: removing it deletes those events. To pause the containers and keep that data, use `docker compose stop`. When you want to remove the containers and their default MongoDB data instead, use `docker compose down`.

## What it is for

Use the console sample to change an event and follow its consumers in Program.cs without adding an HTTP surface. The reactor gives you a terminal observation; inspecting a read model is a separate task. When you need model-bound commands, queries, and a frontend, continue with the [Cratis Web Application](/templates/cratis-web/) template.

## AI assistance

AI assistance is optional; it is not required to run the console sample. The scaffolded project includes a `.cratis/ai.json` selecting the `cratis/application/chronicle-dotnet` profile with the C# language. If you want that guidance, install the [Cratis CLI](/cli/) and run this from the MyConsole project root:

```bash
cratis ai update
```

That installs the AI rules, skills, and harness integration for the selected coding agents (`AGENTS.md` plus `.claude/`, `.cursor/`, `.github/`, `.opencode/`, and `.pi/`) and records what it installed in `.cratis/ai.manifest.json`. `dotnet new` prints this reminder after scaffolding; `cratis new` runs the update for you. Running it again refreshes only Cratis-managed files. See the [CLI AI documentation](/cli/ai/) for the full command reference.
